# 代码组织与职责边界

类型：standard。2026-10-10。以实际调用链决定模块归属，保留当前功能和公共路径。

## Next.js 依据

官方 [项目结构](../vendor/nextjs/2026-10-10/project-structure.md) 允许路由共置、私有文件夹、路由组与应用外的领域目录；并没有要求所有项目采用相同目录。官方 [服务端与客户端组件](../vendor/nextjs/2026-10-10/server-and-client-components.md) 将状态、事件、浏览器 API 放在客户端，把凭据、数据库与文件读取留在服务端。官方 [Route Handler](../vendor/nextjs/2026-10-10/route-handlers.md) 定义请求适配文件的约定。

本项目保留根 `app/`，不为风格统一迁移所有文件到 `src/`。路由与构建约定维持 Next.js 的原生结构，业务模块按真实职责整理。

## 模块归属

| 位置 | 负责 | 不负责 |
| --- | --- | --- |
| `app/` | 页面/布局、metadata、请求和响应适配、必要的运行时/缓存声明 | 大型通用状态、数据库规则、成块的领域算法 |
| `components/<领域>/` | React 展示、交互及局部 UI 组合 | 服务端凭据、文件系统、直接写库、另一领域的全局状态所有权 |
| `lib/<领域>/` | 类型、算法、领域服务和状态适配 | 导入 React 展示组件；通过隐式全局回调绕过契约 |
| `lib/stores/` | 既有 Zustand 状态和状态动作；大型 store 的子目录负责独立职责 | 同时包办 UI、数据格式、迁移、网络重试和存储引擎 |
| `classolo/` | 课堂工作区领域模块和其独立协议 | 复制 Studio/Agent 的身份、模型、文件和计费规则 |
| `scripts/` | 可复现的构建、内容接入、维护与检查 CLI | 浏览器运行时依赖和一次性无入口脚本 |
| `content/`、`lib/content-data/` | 原始内容、注册元数据、生成清单 | 业务运行状态或用户数据 |
| `electron/` | 主进程、IPC、受控本机能力与打包边界 | Web 服务端凭据或向浏览器暴露任意系统命令 |

## 何时拆文件

文件超过 500 行时审查职责，超过 800 行优先处理。行数是信号，不是机械通过标准：生成文件、完整领域数据与单一公式推导不能仅凭长度断言坏架构。测试不为了凑长度拆碎。

发现两个独立变化原因就拆分，例如存储引擎与附件迁移、同步队列与 Zustand 适配、题型输入与评分展示、模型契约与注册数据。新模块命名表达职责，避免 `helpers2`、`misc`、按行号划分和只套一层转发。

拆分时：

1. 查明所有导入、动态入口、脚本路径、测试替身、构建 tracing 和文档引用。
2. 把共享类型放在无运行副作用的契约模块，使用 `import type`；不以类型依赖加载 store 或服务。
3. 将独立算法、转换、适配和展示移到领域子目录；入口只保留组合和边界处理。
4. 更新真实调用者。仅有确切兼容性需要时保留转发入口，并说明消费者及移除条件。
5. 用已有行为测试与必要的新边界测试确认功能，实际浏览器检查用户可见的改动。

## 拥挤目录与依赖方向

同一目录出现二三十个以上人工运行文件时检查领域归类。优先按 composer、rendering、trace、attachments、settings、history 等真实职责分组，相关测试随实现移动。避免一文件一目录和为了减少数字建立无意义深层树。

依赖方向为路由/UI → 领域服务或状态 → 数据契约/基础能力。跨领域共享能力通过窄接口引用，不通过庞大聚合模块回绕。即时运行时循环需要修复；类型与必要延迟加载单独分析，不能混为一谈。

组件需要延迟加载的已有理由必须保留；独立模块不自动意味着浏览器少加载。`use client` 放在需要交互的入口，不将本来可服务端执行的整片树迁到客户端。

## 死代码和重复逻辑

Knip 是线索，不能独自证明删除安全。先核对 Next 特殊文件、Electron `require`、搜索 Worker 编译入口、沙箱 skill-pack、动态导入、CLI、生成脚本和测试。真实入口用配置声明，不增加泛化忽略来隐藏未检查的结果。

重复算法只有在输入、误差、边界行为和消费者一致时统一。相似样式或同名函数不自动等价。公开行为保持，必要差异通过参数或领域适配表达。

## 持久化与服务端边界

持久化格式、所有者作用域、checkpoint、完整历史和恢复流程见 [存储架构](../refer/storage-architecture.md)。重构只能改变代码组织，不能把失败保存假装成功，不能丢弃旧数据来换取精简。

凭据、数据库、文件和计费服务保持服务端归属；类型/展示入口与 `*.server.*`、Agent `tool.ts` 分离。沿用 ESLint 的现有导入边界。路由拆分后保留 `runtime`、`dynamic`、认证、request size、响应头与错误契约。

## 可复现清点

`node scripts/maintenance/architecture-inventory.mjs` 输出源码长度、目录数量和依赖图到忽略的验收目录。它只读取 Git 已跟踪文件，新文件需纳入版本控制后才包含。类型与动态引用单列，循环统计仅考虑即时运行时导入。

文档和事实变化同阶段更新；静态源码清点不能作为功能、性能或生产验收证明。
