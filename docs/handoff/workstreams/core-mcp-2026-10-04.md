## 实际根因与修复

### 1. 真实连接按钮被第一跳 CSRF 守卫阻断

最初的故障现场：主任务在正式已登录页面点击 Google 连接后，新标签停在 `/api/connectors/google/connect`，响应 `{error: "Trusted request origin required"}`。该第一跳阻断不等同于应用未创建或缺少 OAuth callback；修复后的最新实际阶段见下方业务验收。

原连接控制使用 `method=post target=_blank rel="noopener noreferrer"`。HTML 导航表单在 no-referrer 策略下发送 `Origin:null`，与严格同源检查冲突；普通默认 cors fetch POST 不同。机制参见 [MDN Referrer-Policy 的 Origin 影响](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header)及 [rel=noreferrer](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/rel/noreferrer)。

修复：第一跳同源表单仅保留 `rel=noopener`；授权中转页和 callback 响应仍使用 `Referrer-Policy:no-referrer`。`proxy.ts` 保持拒绝 null、缺失和跨站 Origin；仅为连接器拒绝响应补稳定 `ORIGIN_REJECTED` code，HTTP403 与原 error 保留。KitSolo 使用 `window.open` 和 GET 链接，没有该导航 POST 表单，未改 KitSolo 核心。

### 2. 手机市场在卡片渲染前就被跳回课程

主任务的真实 390px 检查发现 `/agent/plugins` 被 AppShell 的 Agent 手机回退跳到课程；此前 `usesMobileStudioChrome` 又使插件 children 受课程 mobileTab 遮挡。此现象不能通过卡片 CSS 修复，也不能当作窄屏已经通过。

修复：精确 `isAgentPluginsPath` 只接受 `/agent/plugins` 与其 `/` 子路径；`/agent/pluginsevil`、`/agent/plugins-other`、资产/定时任务等不豁免。AppShell 仅跳过该管理路径的手机回退；手机插件管理直接显示 children，复用 AgentShell 既有仅中央插槽分支。MobileTopBar 复用现有 ModeSwitcher、AnchoredMenu 与移动模式跳转，显示 StudySolo · Agent，能回记住的 Studio 页面；不显示错误课程标题/章节弹层/Studio 底栏。不开放其他 Agent 页面或手机通用 CLI。

### 3. 卡片与详情存在最小内容宽度冲突

原市场网格固定最小 280px，正文固定横向 padding；卡片将完整连接控制、Google 多项选择及详情按钮横排，标题/版本也争夺宽度。详情的长字段没有正确收缩/换行约束。

修复：网格最小列宽取实际容器宽度与 280px 的较小值；卡片/详情/搜索/连接状态补 `min-w-0`，长名称/错误/字段正常换行，连接控制占完整独立行，按钮可换行；较小屏幕缩小正文 padding。没有用 overflow:hidden 裁掉连接功能。学习连接器结果卡只补自身长服务名/错误/候选按钮布局。

### 4. Google 的前后端权限边界不一致

配置模块只允许已批准五项范围，但连接 UI 和 OAuth 表单处理额外开放 `calendar.events`。此外原 Google discover 披露所有适配器操作，导致当前 grant 不具备的能力仍出现在模型工具发现中。

修复：`google-scopes.ts` 作为前后端共享五项服务范围；表单和服务端均不开放日历写权限。服务端选项只能来自本环境已配置的批准范围，并拒绝伪造的 calendar.events 表单。Google discover 同时要求当前 grant 的实际 scope 和当前批准名单。保留未开放的日历创建适配器代码，不据此授予日历写权限。基本 OpenID/email 只用于提供者身份绑定。

### 5. 授权失败导航与断连结果无法恢复/理解

OAuth2 callback 失败原来只显示 JSON；Zotero 正式失败页面还指向开发入口。成功 query 未被统一消费。原断连只保留布尔 failed，丢掉服务器错误 code 和远端撤销结果；失效 grant 只能重新授权，不能主动断连。

修复：浏览器导航请求由 `connectorBrowserFailure` 回到**固定配置 origin 和固定 `/agent/plugins` 路径**，仅携带白名单 code/provider；不反射提供者正文、用户 URL、state、code、token 或异常消息。API/JSON 调用保留原状态码和响应。Account 限制、邮箱验证、MFA、站点配置、取消、过期及限流使用既有 i18n 分片映射。

市场先查询实际当前账号状态，只有对应 provider 为 connected 才允许成功提示。query 只是导航信息；清理 query、展示一次 notice 和调用既有 Toast store 在同一个可取消延迟提交内完成，StrictMode 取消首轮 effect 不会丢掉提示。

敏感连接/断连触发 MFA_REQUIRED 或 REAUTH_REQUIRED 后，notice保留安全code，复用项目 `accountOrigin` helper 生成准确 Account 链接：MFA→`/login?step=verify&redirect=<当前固定市场>`，再次验证→`/reverify?next=<当前固定市场>`。使用既有链接外观，全页交回 Account；明确 `data-solo-sign-in=page`，普通登录增强器不能丢掉验证参数。没有放松MFA，也不向模型或日志传验证器代码。

断连使用从原 DeleteNoteDialog 抽取的共享 `components/shared/ConfirmDialog.tsx`，复用原 `.app-dialog*`、portal、Esc 和取消行为；原笔记删除组件只是兼容 wrapper，保留原 aria-label/文案。成功反馈明确区分本项目本地阻止与提供者撤销已确认/未确认。服务器通过 `canDisconnect` 指示已验证归属的过期旧 grant；unknown/unavailable 不假定存在可断开的 grant。

### 6. 局部故障与失效状态影响整个市场

原 status 中一个 grant 读取/续期错误可使全部状态失败；明确的提供者 401 可能使页面仍显示 connected。

修复：Account 身份仍先在路由整体验证，不吞掉身份错误；只有提供者存储/续期故障按服务返回 unavailable 或明确 reauthorization_required。状态刷新使用既有租约续期，轮换仍加密保存、版本比较更新。MCP/native API 的明确 401 会按同一当前凭证版本标记需重新授权；迟到的旧请求不能覆盖重新连接后的凭证。断连与候选的单次执行/取消/不确定状态合同保留。

### 7. Google五项选择在同账号MFA刷新后丢失

2026-10-05本机日期的主实测确认：用户最初主动选择五项→connect遇近期身份再验证→同账号session/status刷新暂时清空connections。原uncontrolled `defaultChecked` 控件以 `connection.scopes.join()` 或 `default` 作key，重建时重新默认勾Drive/Calendar；后续真实Google Testing请求因此只剩两项。这个问题是授权意图丢失，不是提供者已经授予五项，也不是通过默认全选可以修好的UX问题。错误两scope提示页未提交并已关闭，尚未保存grant。

修复后的Google选择为受控草稿，复用既有 `getStorageOwner`、owner epoch/change事件、`ownedStorageKeyFor`，只同步保存 `ss-user:<已确认Account owner>:google-connector-scope-draft-v1` 的批准scope数组；不保存token、grantVersion、owner身份对象或学习正文。同账号token/MFA更新不清连接快照/草稿；临时owner未就绪仅清内存视图，同一owner再次确认后读取自己的数组。真正换账号加载自己的草稿或默认两项，迟到的旧owner操作/旧请求不能写入新owner分区。新tab/full-page Account验证返回固定市场时，从该origin的已确认owner分区恢复，而不依赖原React控件仍存在。跨tab storage事件也仅消费当前owner的key。

待授权选择和真实授权分开：状态返回公开不透明 `grantVersion`（绑定及实际scope摘要，不含token/expiry/refresh revision）。普通续期版本稳定；新OAuth绑定或实际权限改变时，界面按真实scopes重新校准。新文档callback提示只有在实际GET connected后才清待授权草稿并采用实际scopes；query与版本都不作为认证/权限输入。旧服务无版本仍能用实际scope保守展示。控件明确标示“下次授权选择”和“已保存的授权范围”；scope草稿不覆盖服务器grant或模型discovery。确认本地断连成功后才清草稿回默认两项，远端撤销未确认不冒充成功；用户之后仍可主动重新选择。GET现有ownerBinding还用于拒绝cookie已在另一tab换账号、AuthProvider尚未完成恢复的错owner状态写入，服务端身份依旧只由Account认定。
