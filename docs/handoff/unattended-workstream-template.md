# 大板块无人值守派遣模板

适用：主智能体根据最新用户指令把`current_phase`从文档整理切为实现后。模板不构成自行启动实现的授权。CORE-MCP与CORE-SANDBOX也由子智能体完整执行；主智能体统筹、审查、验收和整合；子任务只派整个大板块，不把requirements各项拆成新的worker。

## 主智能体派遣前

1. 读本目录README、完整handoff、workstreams账本及最新人类消息；核对git状态、当前基线和是否有活动子。
2. 选择一个大板块，确认前包已主验收；填下方完整上下文。模型用用户指定`gpt-6.1-sol`、`high`（每包强制显式设置，不能回退Luna或继承其他模型），新大板块新worker，同模块反馈继续原worker；最多一名执行。
3. 显式指定读取共享文件中的完整上下文。新worker可用`fork_turns=none`并收到完整任务说明和文档路径，不依赖旧聊天摘要；模型覆盖须遵守工具约束。
4. 将`assigned_agent`、状态与next_step写账本，才开始；需要worktree时按已有附件和仓库规则检查复用，不擅自reset/stash其他工作。

当前真实依赖例外：CORE-MCP和CORE-SANDBOX共享聊天认证入口，由同一CORE-INTEGRATION worker整包联合处理，不另开第二名、不同时改同文件；两项逻辑验收分别保留，联调未过不能closed。先完成账本所列MCP scope草稿，再分析完整沙箱包。新UI等执行组仍须前组主验收后开启。

- 用户可见入口：[实际路由/模式/按钮]，前端主组件：[路径]，接口/存储：[路径]。先在实际页面确认定位，不能以名字相似替代目标。

- 复用合同：[菜单、toast、主题、原Agent案例基线、笔记组件等具体路径]。基础设计统一、无溢出和前端接口优先，不另造样式、不打磨额外UX。
- 已有证据：[局部技术证据及其边界]；用户验收：[当前失败/未过]；需保留：[已正确局部行为]。不要因旧日志重做，不全盘revert。
- 先分析入口/数据/状态根因，发方案；在本包授权范围实施，报告接口是否真的发出、数据是否真实保存。正常可逆修改不反复要许可。
- 自测：[少量必要检查＋关键真实业务流程＋桌面/窄屏基础设计]；运行时由已有RootSolo入口管理，RootSolo用Edge，其余按用户浏览器偏好；不要自行CLI启动/停止其他服务或绕过控制限制。
- 验收需要真实用户入口，mock/匿名截图/构建不能代替；无法完成时精确记录缺口并继续本包独立项，不宣称done。
- 不输出密钥、用户正文或个人联系方式，不替用户输入登录/MFA；凭证只从受限文件/服务端读取并按协议使用，不放进派遣提示或模型历史。不得因失忆重复注册应用或生成密钥。认证/资源配置仅限工作包已授权范围，主审查并遵守现场确认规则；不操作范围外服务器、不超过预算，迁移/发行遵守现行运维。
- 最终回报：根因、修改文件、复用组件、完整接口/数据路径、定向检查、实际页面/业务证据、未验证边界和剩余问题。保存metadata-only证据；不要自行发布/合并或宣布整个目标完成。

## 主智能体验收

独立读diff；核对改动位置、规范复用、真实接口/结果及数据持久性；查看截图和关键业务流程，不重复无意义全仓测试。若不合格，把具体问题交回同一worker。只有本包基础设计和完整功能经过所需验收才改为closed，记录源码/实际运行版本；再开下一大板块。部分通过只更新acceptance evidence，不能改整包为完成。
