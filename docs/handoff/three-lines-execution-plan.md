# StudySolo 三条线执行规则

用户于2026-10-05明确要求实现此计划，取代旧CORE-INTEGRATION优先及生产验收队列。

## 顺序与交付

1. SIMPLE：共享对话/Agent UI → Review/笔记最小业务 → 消息反馈/已有后台 → 浏览器基础操作。
2. SANDBOX：普通命令 → Notes to Handbook和GB原脚本 → 下载/停止/回收。
3. MCP：GitHub/Google → Notion/Todoist/Zotero/PubMed/Crossref，Anki保持导出，Microsoft暂停。
4. 清理两套接入代码：去无引用冗余、合并重复实现、保留必要旧消息/工具ID兼容。
5. 独立客户端收尾：手机Web壳、Electron启动/打包、GitHub发布与下载核对。

每个大板块本机验收后提交任务分支；整条线完成后一次完整CI，再同步主/开发分支。不得整支合入未验收客户端或会员在途修改。网站由用户部署；不操作服务器、不做生产端测/运维。不自动恢复旧定时任务。

## 派遣与范围

每包显式GPT-6.1 Sol High，最多一名子执行，不再派子。相近模块同worker，返工继续原worker。主负责范围、复用与本机独立验收/整合。

每包只确定五点：真实入口、现有复用组件、行为变化、本地验收步骤、排除项。简单包约1小时，初次定位约10–15分钟；超时报告具体阻碍并收敛，不扩体系。新发现默认记待办；直接阻断当前功能或删除用户数据的缺陷才作最小同包修复。

保留正确代码和当前UI候选，不重建。主独占任务账本，状态只保留当前包、已验内容、剩余与唯一下一步；历史技术证据不冒充完成。

## 简单线行为与验收

- UI：Studio真实会话最近5、固定新建、复用右键CloseOther/All；不删历史，保留原4案例并共享初始引导；已有项目加号/60%比例保留，修真实状态/布局恢复。
- 原生工具UX也在UI包：现有tool registry/AI SDK parts → buildTrace/AgentTrace/ToolTraceStep。MCP和云命令参数、结果及确认/取消/下载位于同一步展开区，状态正确、无独立卡片、无第二状态体系；保持已有服务端接口和历史tool IDs，不以隐藏交互冒充复用。仅验证本机普通读取及失败/待确认场景，不开收费云资源。
- Review：复用已有questionResults.id/questionKey/题集关联/成绩记录，修漏存漏读及prompt，答题→保存→刷新→错题诊断/章节题；笔记一级树、编辑/TOC、选区与基础交互。默认不新增第二题库/成绩API；只有证实缺字段才最小迁移。
- 反馈：原组件/接口/列表，先记录操作再说明，本机提交→后台同条可见，不重建管理系统。
- 浏览器：已有桥接/外部打开、真实缩放/复位/刷新；不新增代理或全面重构。
- 所有页面桌面/窄屏基础检查，用公开材料/自建测试，不输出私人正文。只做必要定向测试；冻结后提交，整线才完整CI。

## 后两线最小闭环

沙箱沿用既有模板、隔离、超时和预算，只独立Agent可执行。原生步骤显示真实命令/两个完整技能/产物下载及回收；不扩调度/云运营系统。MCP复用已有应用、密钥及授权，连接→回站→读取→刷新→断连/失效；直接后端调用不依赖云电脑。两套代码清理在跑通后集中一次完成，不重新造架构。

## 固定边界

不动无关修改、不删用户数据、不泄露凭证；阿里本轮/月新增各≤100元、原runID不重置。登录只暂停依赖步骤。Supabase/MCP认证管理用Chrome；阿里/宝塔/RootSolo用Edge；按各agent自己的实时浏览器family绑定，不跨会话搬数字ID。常规已授权实现不重复请求许可。
