## 用户可见变化

1. 云文件进入原「全部／文件」聚合，计数、搜索、排序、橱窗和列表统一生效。「云端文件」页签使用相同AssetCard和筛选逻辑，额外管理pending与软删除记录。
2. 新文件详情使用`/agent/assets/file/cloud-<UUID>`，提供元数据、原文件下载、引用到对话、待上传确认和二次确认删除。旧的本机导入记录与原详情路由保留。
3. 新上传记录带cloudFileId，聚合只按明确ID去重。不会把同名但不同文件猜成同一资产；失败的上传不再生成“成功导入”的本机记录。
4. 首次读取云端时显示加载与未完整计数；服务失败显示错误并保留已有本机内容，不把失败写成“没有资产”。刷新等待相关实际请求，取消固定900ms结束转圈。
5. 课堂缓存排除归档项；返回资产页重新合并读取课堂清单，云查询失败保留本机课堂并提示。同步角标订阅真实云行索引变更。
6. 手机`/agent/assets`及其详情使用现有管理页外壳，不再跳回Studio；豁免路径精确，不扩到Agent工作区或云命令。
7. 没有真实时间戳的演示不再把数组序号显示为1970年日期，时间与排序顺序分开。

## 架构边界

| 层 | 入口 | 唯一责任 |
| --- | --- | --- |
| 引用与文件合同 | `lib/files/contract.ts` | 9个/25MiB、稳定URI、统一引用收集和composer计数 |
| API客户端 | `lib/files/client.ts` | 请求绑定期望owner、响应epoch检查、分页/游标保护、运行时结构校验；只首屏读取额度 |
| 云文件共享快照 | `lib/files/library.ts` | 同账号请求去重、首次/后台加载、错误、每文件操作锁、owner/epoch/revision迟到保护 |
| 文件变更通知 | `lib/files/events.ts` | pending/ready/delete语义通知；删除让本机项目索引立即失效 |
| 课堂元数据 | `lib/agent/classroomAssets.ts` | 单独维护课堂来源的读取/缓存/错误，不放课堂正文进资产聚合 |
| 纯资产聚合 | `lib/agent/assetCatalog.ts` | 本机与云来源转成统一AssetItem；筛选/排序/计数，不直接联网或认人 |
| 页面与详情 | `AgentAssetsPage`、`CloudFilesPanel`、`CloudFileDetail` | 消费同一云库，复用卡片和ConfirmDialog；不再各建一份云文件请求状态 |
| AI接续 | `collectCloudFileIds` → 检查点/请求 → server resolver → 既有项目工具 | 稳定ID读取，压缩不依赖摘要逐字复制URI |

云文件库是元数据快照，不是第二套会话存储、计费系统或执行框架。服务器继续实时Account认人；客户端期望owner仅作一致性校验，不是授权依据。

## 独立审查发现与修复

| 级别 | 实际触发路径 | 处理结果 |
| --- | --- | --- |
| P1 | 同名文件按新到旧恢复，beginImport按名字复用ID，旧版覆盖新版 | 每个名字仅恢复最新有效云版本，旧不可变文件保留在资产库；最新deleted作为墓碑，不能自动装回旧版本 |
| P1 | 上传后再次异步解析，切账号后的结果写入新账号store | 复用已提取文本同步切片，核对owner；主另补处理后上传前的owner核对，旧账号文件不会上传给新账号 |
| P1 | 从详情引用的ID在用户text中，压缩仅收集attachments，摘要未保留URL就丢目录 | 附件、file part、用户文字统一收集ID，进入手动检查点、自动检查点和后续请求；即使AI摘要不含URL仍能接续 |
| P2 | 全部/文件不含真实云文件，旧详情仍写文件不上云 | 统一聚合与云详情；稳定ID去重，保留旧本机记录兼容 |
| P2 | pending确认重复点击、旧owner完成回调刷新新账号 | 单文件操作锁，统一客户端owner/epoch与共享库revision校验 |
| P2 | 老刷新在删除后返回，重新显示已删文件 | 变更通知和mutation使旧请求失效；成功软删除即时更新，再读取权威状态 |
| P2 | prepare产生pending/预留，后续失败但资产库不失效 | prepare/确认/取消分别发送pending/ready/delete；自动取消复用同一删除通知 |
| P2 | 引用1个云文件再上传9个，上传后才被服务器拒绝 | 添加/发送前合计并去重引用，服务端复核总数，保留具体限制错误 |
| P2 | 首次慢云请求先显示完整空资产清单 | 加载与计数未完整文案；请求错误不能成为成功空态 |
| P2 | 课堂归档仍在本机缓存，失败退空且返回资产不刷新 | 排除archived，保留显式错误，挂载去重刷新 |
| P2 | 云行状态变化不通知，同步角标不更新 | 增加专用云行索引订阅，聚合随快照变化重算 |
| P2 | 首页重复GET，每分页都读取会员额度 | 合并列表+首屏额度返回，共享单请求，后续分页只查文件 |
| P2 | 演示顺序冒充时间 | 使用独立sortOrder，无真实时间显示未知 |
| 主整合检查 | 已移除导入占位在上传完成后被重建成残缺记录 | 确认占位仍存在，否则停止回填并对精准已上传文件执行软删除清理 |

## 保留的运行边界

本机文件变更通知可及时更新同页面的共享快照；另一设备或另一标签页的云变更仍需刷新/重新读取，本轮没有引入Realtime或承诺跨设备实时订阅。基础软删除没有物理清理或恢复UI；供应商实际占用由之后的保留期/清理方案处理。图片仍需支持图像输入的模型，旧PPT/扫描PDF等保持原解析兼容边界，不将“稳定引用”写成任意格式都已被AI完整理解。

新增迁移已应用，正常账号端测仍需补：新照片/文档在全部与文件出现 → 搜索/排序/详情 → 引用并实际读取 → 压缩后追问仍可读取 → 确认软删除并校对额度/项目索引 → 手机清理入口 → 刷新/另一设备恢复。网站部署仍由用户负责。
