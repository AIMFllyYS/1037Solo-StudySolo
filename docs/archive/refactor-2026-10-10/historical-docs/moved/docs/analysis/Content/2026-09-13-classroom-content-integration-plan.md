## 0. 结论与范围

**建议做一个“小型课堂内容接入层”，不是重构整个学习平台。** 一个仓库；四份文章按课集中存放；一份课堂 JSON 表达身份与题库关系；可信构建程序派生导航和注册；已有 Markdown、HTML、题库及窗口能力按差异补齐。

最小目标是：负责同步的 Agent 拿到四类材料，按约定处理后，只提交本课的内容、元数据、题库和实际依赖资源；平台无需每次新增路由、组件或手工改中心 manifest，就能正确展示和检索。

### 0.1 用户已确认，不再重新讨论的事项

| 材料角色 | 平台收到／保存什么 | 处理方式 | 本课自动出题来源 |
|---|---|---|---|
| `recording` 课堂原文 | 原始课堂逐字转写文本 | 忠实保留，以纯文本阅读 | 是 |
| `minutes` 课堂纪要 | 独立纪要 Markdown | 可充分重组，适配现有富文本契约 | 否 |
| `notes` 课堂笔记 | 已做可视化的 HTML | 保留成品，不重写为组件文章 | 是 |
| `cards` 复习手卡 | 闪卡 Markdown | 按项目富文本与记忆卡能力重新组织 | 否 |

四类是课堂材料角色，不是取消教材、详解、考前模拟、实战演练等既有学科分类。每份材料文件是一篇独立文章，同一课程节次下聚合展示。第7—8节作为来源明确的一次课堂单元，不擅自拆为两套文章。

来源位置、课表匹配、上游材料生产、PPT 的获取与部署，由现有负责 Agent 掌握。本文不设计音频上传／播放器、PDF 必交、PPT 转换服务、飞书知识图谱同步、记忆调度、Agent 运行时重构或人工编辑冲突系统。

“HTML 窗口正常点击”落实为：文章打开、全屏、独立阅读窗口／新标签、普通链接与锚点按预期工作。不能推导成必须实现跨 iframe 划词提问、HTML 内编辑器或任意脚本执行。

### 0.2 决策成熟度

- **已确认需求**：上表四类角色、出题来源、同仓分层、不改写现成 HTML、允许 MD 充分适配、Agent 维护材料。
- **本文推荐方案**：集中课堂目录、构建派生注册、四篇文章复用现有三段路由、课堂级题库键、手卡新增兼容模式。
- **待实施核验而非现在阻塞的问题**：云端具体触发方式、GitHub 合并权限、实际发布目标分支、HTML 在目标浏览器的表现。下文给出必要条件，不宣称已配置或已验收。

这不是“改一个 manifest 就完成”，也不是“大改整个应用”。它属于可分批实施的中等规模内容接入改造。主要风险是多个消费者必须得到同一个课堂身份和内容版本。

## 3. 目录方案比较与明确推荐

### 3.1 三种选择

| 方案 | 优点 | 代价 | 判断 |
|---|---|---|---|
| 全部保持旧平铺目录，额外添加 notes/cards | loader 变动较小 | 同一课堂分散在多处，四类关系仍需清单，中心注册冲突仍在 | 可以应急，不作为推荐长期方案 |
| 新课堂按课集中，旧内容不动 | 日常 PR 集中；来源清楚；渐进接入 | 一次性增加目录解析、生成注册与校验 | **推荐** |
| 全库迁移到新通用资源系统 | 形式统一 | 历史链接、题库、路径和所有分类一起受影响 | 超出当前必要范围 |

不拆仓库、不加数据库/CMS、不先迁全部旧内容。课程资源少时，普通文件与 Git 已经足够。

### 3.2 推荐目录（新增建议，当前尚未创建）

```text
content/
├─ instrumental-analysis/
│  ├─ textbook/                              原有教材不动
│  ├─ detail/                                原有详解不动
│  └─ lectures/
│     └─ 2026-fall-007-008/
│        ├─ lesson.json                       唯一作者侧课堂声明
│        ├─ recording.md                      扩展名保留MD，阅读语义为纯文本
│        ├─ minutes.md                        平台富文本纪要
│        ├─ notes.html                        已有可视化笔记
│        ├─ cards.md                          平台富文本手卡
│        └─ assets/                           仅在有实际依赖时出现
└─ quiz/
   └─ instrumental-analysis/
      └─ rec-2026-fall-007-008.json            继续兼容现有题库根目录

lib/content-data/
└─ lectures.generated.json                   建议新增：程序派生，不人工写
```

使用 `recording.md` 而非强制改成 `.txt`，是因为实际样例已经以 MD 封装原文；**扩展名、材料角色、渲染方式是不同概念**。导入仅统一 UTF-8／换行，不重写原文；渲染器以转义文本和 `white-space:pre-wrap` 展示，不把尖括号、指令或公式当可执行／富文本内容。

`2026-fall-007-008` 是可读稳定 ID 的示例，而不是按每次标题或日期重新推导的强制公式。课堂 ID 首次分配后固定；补课改日期、修改主题不更换ID。同课程实例存在相同节次的独立教学事件时，由上游追加稳定后缀，不能自动拼接两份内容。名称中的“第7—8节”是课程内累计节次，不是全天第3—4节。

分析化学 → `instrumental-analysis` 是基于当前项目已有仪器分析学科及前序样例的推荐映射，需在一次接入代码变更中显式批准。**不能因为名字含“化学”就映射到 `chemistry`，后者是有机化学。** 人体组织学／细胞生物学／生化同样使用明确别名表，不靠每次模糊猜测；遇到无匹配学科停在待映射，不自动塞入全局 other。

### 3.3 最小课堂声明

以下为说明性数据示例，不是已生效 schema，也不应未经实现直接入库：

```json
{
  "schemaVersion": 1,
  "subjectId": "instrumental-analysis",
  "courseInstanceId": "2026-fall",
  "lessonId": "2026-fall-007-008",
  "courseName": "分析化学",
  "sessionRange": { "start": 7, "end": 8 },
  "taughtOn": "2026-09-11",
  "topic": "萃取技术体系与紫外可见分光光度法基础",
  "revision": 1,
  "materials": {
    "recording": "recording.md",
    "minutes": "minutes.md",
    "notes": "notes.html",
    "cards": "cards.md"
  },
  "quizId": "rec-2026-fall-007-008"
}
```

v1 固定材料角色及文件名，拒绝任意额外 key 和路径。sourceRef／源版本可作为补充字段由上游提供，但不要因此要求平台发现云盘资源。来源内容哈希、笔记有效文本哈希和题库绑定的输入版本需要被校验记录，不能仅靠 revision 自述。

初期可由提交 Agent更新 `revision`，CI 校验版本与目标分支一致；文件哈希由工具计算，不让模型手填猜测。新增版本不能覆盖更高 revision。Git 记录包历史，无需另建修订数据库。

### 3.4 同步文件边界

日常最小内容 PR 是五个课堂文件＋一个题库 JSON，另加确有引用的资源及按仓库政策纳入版本控制的确定性生成文件。生成目录允许变更不代表作者可以自由编辑：必须由可信程序重算并逐字比对。

不提交说明README为第五篇文章；不复制原输出目录的 Python、封面／正文中间文件、未选择发布的PDF、完整KaTeX依赖、日志、原始云盘认证信息。四类已选择材料才是发布清单，未知文件报“未选择／不支持”，不能静默当学习资料导入。

## 4. 注册与路由：保留现有骨架，不在客户端扫文件

### 4.1 推荐生成链路

```text
各课堂 lesson.json ＋ 四份材料
   → 独立构建脚本：schema／路径／完整性检查
   → lectures.generated.json（元数据与可序列化条目，不含正文）
   → manifest 适配合并：旧items ＋ 新课堂groups
   → nav.generated.json ＋ 静态页面参数
```

关键限制：当前内容数据被客户端状态／布局组件间接导入。**不能在 manifest 或客户端可达模块里加入 fs.readdirSync、正文读取或扫描目录。** 文件扫描仅在独立生成脚本和服务端loader；运行期客户端只接收纯JSON／纯函数结果。

新生成器应从独立的schema／学科配置读取，不依赖最终manifest，避免“生成器需要manifest、manifest又需要生成结果”的循环。空目录也要生成合法空catalog；生成脚本只改指定生成文件，不重写内容。

开发启动、生产构建、CI检查都先执行课堂生成，再生成导航，再执行一致性检查。短期沿用现有“生成文件入Git”的习惯更便于兼容：本地生成后提交，CI用基线可信生成器对候选内容重算并检查差异；校验阶段不能偷偷修好然后报成功。长远是否取消生成文件跟踪不影响本期，应避免半数流程入Git、半数只构建生成。

### 4.2 四篇文章共享课堂，不共享 article ID

建议新课堂四篇文章先全部挂在现有 `recording` 分类内，避免初期引入跨分类别名与新路由层级。例如：

```text
/instrumental-analysis/recording/rec-2026-fall-007-008
/instrumental-analysis/recording/min-2026-fall-007-008
/instrumental-analysis/recording/note-2026-fall-007-008
/instrumental-analysis/recording/card-2026-fall-007-008
```

文章ID由课堂ID＋材料角色确定；真实文件从受控课堂目录解析，不再假设 articleId.md 就是落盘文件。保持三段路由，不把用户可见文件夹深度绑定到URL。

文章带 `lessonRef` 和 `materialRole` 等可选扩展；新课堂父节点用显式 `navigationOnly` 或等价标记。现有 section/document 类型可保留，不必全库改为全新节点类型。不得简单过滤所有“有children”的节点，因为某些旧章节父节点确有正文。

保留全局六个标准分类的名称／顺序／默认能力，避免破坏既有一致性测试。新课堂材料的有效能力由中央解析函数计算，而不是修改 recording 模板让所有旧录音退化或强行获得新能力。

### 4.3 旧纪要分类与新课时树

首期：旧 summary 分类及其链接保持原样；新课堂纪要在课时文件夹内可达，不另外复制一份 sum文件。以后若需要在 summary 中汇总全部新纪要，再添加明确目标的“导航引用”，其实际读取与索引仍只指向一份canonical内容。

这是减少首期改动的推荐取舍，不是要求永久删除纪要汇总。尤其保留生化既有独立 `sum-01`，不能自动把它改归“第一讲录音纪要”。

### 4.4 导航必须同时验证的消费者

桌面树、移动端 ChapterGroup、兄弟文件面板、首页开始学习落点、面包屑、高亮／展开、预取与静态参数需使用一致的节点语义。客户端 `getContentItem` 已递归，但服务端查找和检索部分只处理一层children；首期只有“课时→四材料”一层，同时逐步共用遍历助手，别在树里先叠出任意深层学期／材料文件夹。

新生成导航需要保留“这是仅导航组／实际目标”的必需字段，不能只往 ContentItem 加字段却被瘦导航丢掉。无需把全部 source、物理路径、来源文本发给浏览器。

## 5. 统一内容读取：显示和机器读取是两份表示

建议在内容层定义一个小型标准读取结果，语义上包括：canonical路由、材料角色、渲染格式、显示内容／安全HTML入口、可搜索文本块、课堂与题库引用、内容版本。

这是“统一信息结果”，不是要求所有格式都变成同一种字符串。现有Markdown函数可以继续保持语义，新增统一入口由新调用方使用，不能把HTML随意塞进名为readContentMarkdown的返回值。

| 内容 | 用户看什么 | 机器读什么 |
|---|---|---|
| 原文 | 转义纯文本，保留段落、说话人与时间戳 | 以说话轮次为单位的文本块，长轮次拆块并继承定位 |
| 纪要 | 项目富文本正文 | Markdown AST文本与标题层级；用于检索而非本课自动出题 |
| HTML笔记 | 既有HTML视觉版式 | 解析DOM所得文本块、表格行列、公式／上下标与章节／页定位 |
| 手卡 | 原生手卡富文本 | 每卡知识点及正文，用于检索；不作为本课自动出题输入 |

### 5.1 HTML提取不能用简单去标签

本样例表格若直接取紧邻textContent，会变成“参数定义公式特点分配系数…”；单纯删除标签会丢失单元格关系，`sub/sup`、不等号与星号也可能变成另一种含义。应按DOM节点建立段落／表格行列分隔，保留例如 `V_O`、`π*` 等语义，排除style/script、装饰emoji、重复页眉页脚。

本样例主要标题是 `.page-title`、`.section-title`，不是h2/h3。v1可提供针对已批准上游模板的提取适配，h标签作为通用回退；模板结构发生变化而无法提取时，应报错或转人工检查，不能返回一段空文本后继续出题。

提取结果由程序派生并绑定源HTML哈希，不要求Agent再维护一份独立notes.md。不要把旧output中更长的笔记MD当作新HTML的等价替代源；用户已经明确本课出题依据是原文＋发布的课堂笔记。

### 5.2 原文完整性优先于索引长度

约36,000字符的原文完全可以保存为一篇文章，不需要为了检索切成多篇页面。索引按173处说话人标记及段落构建块，块定位保留原文位置；同一时间多个说话人使用段落序号区分。

当前chunker先调用stripMarkdown，再按Markdown标题切分，而stripMarkdown已经去掉#；其中不足最小长度的中间积累段还存在被跳过的分支风险。**新原文接入不能简单复制旧切分逻辑并假设完整覆盖。** 可以为新材料增加明确的分块路径、先不改历史结果，并验证所有正文片段有对应块，不丢短问答、结论或时间戳。

检索去重／切分是程序步骤；语义取舍是Agent步骤。切分器不能决定“这句话不重要所以丢掉”。

### 5.3 覆盖主页面之外的读取入口

需同步适配 `/api/section` 的新格式结果或另设兼容入口、NoteCitationViewer 和当前页／指定页面读取。保留旧 `{content}` Markdown调用兼容；新字段需明确格式，不让旧NoteRenderer接收整段HTML。

Agent工具重构不在本期范围，但当前 `getCurrentPage`、`getSection` 仍调用Markdown读取。内容层可准备统一接口和兼容测试，由Agent重构负责方在其接入点消费；不要在本任务顺带移动工具目录或更换运行时。**这个接口交接未完成时，不能宣称HTML已对平台所有AI读取入口可用。**

## 6. HTML阅读、窗口与点击：小改动，明确验收

### 6.1 首期策略

样例没有脚本与外部依赖，优先按“静态HTML制品”处理：保留原HTML与CSS，不重新转换为组件，主页面和引用浮窗共用一个HTML阅读组件。复用ManagedWindow与既有全屏策略，不重写窗口管理器。

建议为HTML提供稳定的受控阅读URL，窗口打开该URL。当前主页面新标签用Blob拼内容；无依赖样例可工作，但未来相对资源在Blob下可能无法定位，直接打开未受约束的HTML还会形成不同安全边界。稳定阅读页／资源入口应校验内容已注册、已发布，且与主页面采用同一安全策略。

如果首期继续使用srcDoc，也必须使新窗口与嵌入窗口共用同一净化／隔离规则，并解决相对URL，不允许只在主页面安全、弹出后放松。

### 6.2 点击行为清单

- 侧栏点击笔记 → 正常打开；点击其它材料 → 内容与标题同步。
- 全屏按钮 → 沿用已有notes／viewport设置；退出还原布局。
- 独立阅读／新标签 → 用户点击触发，防止弹窗拦截；不传递可控制父页的opener。
- 普通外链 → 仅允许已批准协议，点击可到目标；原文件无链接不意味着已验证。
- 内部锚点 → 在笔记阅读器内定位；若源文件缺锚点，先提供页／节定位回退，不声称支持精确跳转。
- 资源相对路径 → 在明确的本课assets范围内解析；不使用本机file路径。
- 浮窗最小化／恢复／关闭及手机滚动 → 不被iframe抢焦点或层级遮挡破坏。

因此实施验收除了真实样例，还需要一份仅用于测试的带锚点、外链、相对图片和非法链接样本，不能拿这份无链接HTML验证全部点击功能。

### 6.3 保留排版与安全不是对立选择

当前HTML iframe同时允许scripts和same-origin；不能把它直接当成自动内容PR的安全通道。静态笔记默认不允许脚本／事件／任意联网，使用合适的sandbox和CSP约束；普通新窗口链接需要配套的弹窗权限和目标处理，不是加回全部权限。

后续某篇HTML需要脚本时转为“受控模板能力变更”，先审核固定运行时，再允许内容使用。不要自动执行交付包附带Python或JS来渲染。样例可直接静态接入，因此无需为潜在任意HTML提前搭独立渲染服务。

### 6.4 固定A4版式的真实限制

`.page`固定尺寸且overflow:hidden。桌面上可保留原尺寸或适应宽度；手机需明确缩放、横向浏览与打开独立阅读页的策略。容器放大无法恢复已经被页面内部裁掉的文字；若发现裁切，应回到上游修正或采用经批准的显示样式覆盖，不能靠“文件存在”放行。

浏览器实际字体可能影响换行，不应在未截图验证的情况下宣称完全保真。本轮只做静态检查，没有浏览器视觉／点击验收。

## 7. 纪要与手卡的具体富文本方案

### 7.1 纪要：以教学语义组织，而非复刻会议软件栏目

样例“总结”把很多列表粘在长行，“智能章节”保留时间点，“关键决策”和“金句时刻”来自上游摘要产品。建议整理为：本课概览、主题知识梳理、教师明确要求／作业、易错辨析、带来源时间的课堂片段索引。确有价值的原话可以保留，不强行保留会议式标题。

现有definition、note、pitfall、compare、derivation等指令按语义选择。不要把整份纪要再次写成详解教材；允许重组不意味着必须无限扩写，也不依据“每篇至少N个组件”验收。

保留“无需背诵”“仅举例”“条件来自某文献而非通用值”等限制信息。样例原文在13:37明确某镍残留案例仅了解，不应用模板给所有案例一律加“必背”。智能章节的时间有近似偏移，引用原文时按实际文本核对，不能伪造精确匹配。

### 7.2 手卡：复用MemoryCard，增加一个小而明确的模式

样例16个知识点可以先各自成为一张或少量拆分手卡；章节是文章内部标题，卡片不是新增文章。每卡标题应可作为自问问题，正文保留“直接结论、解析、助记、适用条件／易错点”。知识复杂时允许多卡，不能只为凑固定数量拆散上下文。

当前默认MemoryCard逐行构建ChecklistMarkdown；简单行内公式有测试支持，但多行表格和`$$`公式逐行渲染会失去块结构。`mode=cloze`还会识别下划线，不能随意用于带大量公式下标的整段内容。

推荐新增显式 `mode="reveal"`：展开后把完整raw正文交给现有 `QuizMarkdownBase` 一次渲染，不逐行分割；旧默认清单与cloze行为完全保留。这是建议的新模式，目前并未实现，当前写该值仍走旧逻辑。

示意写法（需能力上线后才可用于内容PR）：

````markdown
### 1.2 分配系数与分配比

:::memory{label="分配系数 KD 与分配比 D 的区别是什么？" mode="reveal"}
**直接结论**

分配系数针对指定形态的平衡浓度；分配比针对两相中该组分的总分析浓度。

**解析**

| 参数 | 关注对象 |
|---|---|
| $K_D$ | 指定形态 |
| $D$ | 所有计入的形态 |

**助记**

先辨形态，再看总量。

**易错**

不能仅凭“存在多种形态”断言 $D$ 一定更大。
:::
````

此例说明结构，不是在本轮生产正式学科内容。卡内不嵌套另一份指令registry；复杂提示块可放卡外或使用普通段落。继续保持`QuizMarkdownBase`不依赖registry、MemoryCard不反向导入QuizMarkdown的既有断环约束。

8,192字符raw上限当前超出后会回退有损提取，应在新手卡验收中对单卡超限报错，而不是盲目调大上限。初期不新增SRS、持久化掌握程度、记忆调度或卡片数据库；这些与文章展示是不同任务。

## 8. 出题与质量：两类输入，不能用“都由AI生成”相互证明

### 8.1 本课输入契约

出题输入只包含本课recording和notes的有效文本及定位。minutes、cards、README和任意补充稿不进入输入，不从通用搜索结果拼题。保留原文细节、以笔记帮助校准与组织，但二者冲突时标待核，不自动认定任何一方无条件正确。

原有“主动回忆题”不需要专门规则。题库仍用项目既有题型JSON；题量、题型和难度依据本课范围与学科策略，不强制每次100分，也不把上游知识图谱新增34条误当作必须出34题或必须生成34张手卡。

每题有来源：至少指向允许角色的canonical路由／文件与资源版本、原文时间／段落或笔记页／节定位；可以兼有两类来源，不要求每一题都机械引用两者。来源所在课堂正确不代表答案正确，数值、单位、适用条件与推导仍需审查。

### 8.2 样例说明为什么仍需校验关键结论

HTML第106行和闪卡第39行都写道：“当组分在水相有多种形态时，D通常大于KD”。仅由给出的定义不能推出这个结论。

在有机相只有指定形态A、所有浓度按同一分析物计量基准表达的常见条件下，令水相该形态分数 `α_W = [A]_W / C_W`，则：

```text
K_D = [A]_O / [A]_W
D   = [A]_O / C_W = K_D × α_W ≤ K_D
```

若两相都有多种形态，则需比较两相分数（`D = K_D × α_W / α_O`），更不能用“水相形态多”无条件判断大小。本例是对推论的条件化反检，不替代整课权威教材审校。

这说明HTML与手卡的同一句话可能是同源传播，而不是两份独立证据。上游已有知识校准是重要优势，但不能等同于发布后的“答案正确性已证明”。这处问题应作为试点内容需核对项返回负责Agent，本轮不更改任何样例文件。

同样，“同等总溶剂量分n次”的公式必须明确 `V_O` 是每次体积；固定总量 `V_T` 时每次应代入 `V_T/n`。正式题目需给条件，不能只复制一个n次方公式就认定推导完整。

### 8.3 低成本且可实施的质量门禁

结构检查全自动；语义核对由内容生成／校验Agent负责。关键公式、数值、绝对断言、教师“必考”标记和学科术语应有针对性检查结果。CI可以验证题目有来源、索引在范围、公式能解析，但不能证明全部专业知识正确。

建议试点先人工或受控Agent确认高风险结论，再开放常规内容自动合并。异常进入需核验状态，不允许为了完成四件套而自动修饰争议内容、修改原文或拿纪要来投票判正确。原文保真保留错误发言也是合理的；发布解释与题库则应区分原话和纠错。

### 8.4 题库修订与幂等

保存题库绑定的recordingHash与notesTextHash（以及使用的规范版本）；样式变化不应改变可识别的语义文本。指纹规则不清楚时宁可重新核验，不要声称能完美识别所有语义等价改写。原文或笔记语义更新而题库未重验，则不能宣告完整闭环。

同一课堂同一版本重复提交应无操作；材料仍在生成时不扫描到半个文件就提PR；两Agent同时更新时校验目标版本／源版本，较旧任务不得覆盖新版本。可用规范化diff、Git基线和一个revision完成，不需数据库锁系统。

当前答题恢复以question ID重合率为主，达到50%可恢复，未绑定内容版本。建议先给新题库加可选revision／指纹，并仅对新题库启用精确版本检查；实质换题使用新ID。旧作答记录保留，但版本不兼容时不恢复当前会话或重新按新答案解释旧成绩。不是现在就迁移所有历史作答。

## 9. 学科差异与“其他资料”的可控扩展

### 9.1 学科差异只进入规则与内容，不进入十三套页面

| 学科／类型 | 纪要与手卡应优先保留 | 本课题库应重点检查 |
|---|---|---|
| 分析化学／仪器分析 | 原理、条件、单位、流程、谱图解释；案例条件与通则分开 | 公式前提、单位、方法选择、干扰因素 |
| 概率论／医学统计学 | 定义、适用条件、变量类型、推导／结果解释 | 模型假设、统计前提、不能只背公式 |
| 大学物理 | 对象、方向、量纲、模型、边界条件 | 单位、符号、近似前提及计算 |
| 有机化学 | 结构、反应条件、立体关系与机理 | 命名、结构辨析、反应条件缺失 |
| 解剖学／组胚 | 方位、毗邻、形态、鉴别、发育阶段；真实图来源 | 图缺失则不出无法作答的识图题；方向和标注一致 |
| 细胞生物学／生化 | 结构与功能、调控机制、实验依据 | 机制条件、名词准确、不得把类比当正式定义 |
| 细胞实验 | 目的、步骤、对照、观察、误差与注意事项 | 操作逻辑、对照设计，示例数据不是实测结果 |
| 医学英语 | 术语、语境、词形与句法 | 阅读／翻译内容充分，介绍课不硬凑知识试卷 |
| 近代史／毛概 | 概念边界、时间／背景、因果、教材语境 | 史实与解释区分、材料依据、论述范围 |

学科规则集中在受控配置／SOP，内容PR选择已批准规则版本，不允许降低自己的检查标准。课程实例覆盖教材版本与教师要求；不更改原有教材、试卷的注册职责。

### 9.2 “其他资料”是第二阶段扩展，不是第五种强制课堂材料

后续独立的词汇表、图谱索引、实验补充、专题文章、讨论资料，可在对应学科的 `extras`（建议ID）中登记。有真实内容才显示；默认Markdown或受控HTML，复用同一加载／阅读／校验基础。

如果补充内容直接用于本课理解，可由课堂JSON引用资源ID；跨课资料只保留一个主文件，多课引用。不要把教师课件复制到每节课，也不在每个学科新增十几个顶层分类。

现有全局other是杂项学科，在部分检索链被排除，不能充当所有学科附加资料的垃圾筐。extras是否参与检索与是否参与本课自动出题分别控制；本期固定出题来源仍只有recording＋notes，不能因extras存在就自动扩充出题范围。

新增extras目录时需要接入注册／孤儿检查，不能先放目录再依赖扫描兜底。未知资源类型报告待分类，不凭模型自由增加路由或组件。

## 10. PR、构建和发布边界

### 10.1 内容PR与代码PR分开，但仍在同一个仓库

一次性代码PR建立schema、生成器、阅读方式和校验。后续常规课堂PR只改批准内容路径；首次新增学科、改变富文本语法、开启HTML脚本或修改校验规则都属于代码／能力变更，不混入常规内容自动合并。

准入不能只看作者是Agent或标签为content，也不能把整个content目录无差别放行。检查当前PR全部文件、重命名／删除、体积、资源引用与受影响课堂；禁止依赖锁文件、工作流、脚本和未知可执行资源夹带。

schema和检查程序来自受信任基线。先做路径／扩展名／schema预检，再以无生产密钥的隔离环境读取／构建候选内容。尤其不允许先import未经检查的TS注册变更，再验证它“只是数据”。推荐的JSON接口可以消除日常TS执行风险。

### 10.2 建议的实际顺序

```text
获取明确四材料 → 内容适配／两源出题 → 本地检查
→ 创建或更新本课PR → 当前head上的可信校验与预览
→ 满足合并要求 → 合并后的准确提交生成内容注册／导航／索引／页面
→ 候选发布验证 → 激活 → 四文章／题库／检索复验 → 回执
```

云端Agent已有的来源与部署知识继续使用，不另造调度服务。这里只规定它必须交付哪些结果，以及失败时不能跳过哪些检查。

候选检查绑定head SHA和基线；PR追加提交后旧通过结果失效。重复事件按课堂ID／revision／commit去重。实际GitHub令牌和事件是否触发CI由部署方联调，不依赖文档中的笼统假设。

### 10.3 索引与上线一致性是硬条件

现有prebuild含多项检查，但不执行test:content或build-index；`.index/`被Git忽略。合并PR不会自动传递本地索引。必须由部署方为最终内容版本生成／获取匹配索引，和页面一起发布。

`getIndexHealth().ok`当前不能独自说明内容已同步，内容哈希不匹配主要是warning；发布检查需单独确认contentHashMatch。索引hash只覆盖索引文本，不涵盖题库及所有HTML样式，发布描述还要绑定Git提交与题库版本。

不要把当前BM25-only分支保留的向量默认认为已与新正文一致；它按chunk ID复用缓存，需先对变化文本使旧向量失效，或明确禁用旧向量再标记关键词模式。索引模式、覆盖率与新内容检索结果均应被验证。

构建、校验与资源拷贝在候选产物中完成，不覆盖正在服务的内容。激活失败保留旧版本；回滚同时恢复内容、页面、题库和索引版本，并处理进程缓存。较旧的慢部署任务不能在较新版本之后激活。

### 10.4 草稿不是访问权限

当前draft并不是所有路由／API／索引共同执行的隐藏状态。新未完整课堂留在未合并PR或明确不被发布catalog采纳的暂存区域，不能靠设置draft就假设外部读不到。若未来允许部分材料先上线，需要另定部分发布契约，本期默认四材料＋题库完整后才算闭环完成。

发布文件若含来源私有链接或课堂个人信息，遵守现有站点访问范围；本次不改变公开权限。不往public目录额外复制私有来源记录。新内容路径的文件tracing与构建复制需确认，但不把Web发布扩展为每课发行Electron安装包。

## 11. 具体实施计划：四阶段，不同时重写所有系统

下列均为未来建议；没有执行代码修改、创建这些接口或启动PR。

### P0：固定最小契约与真实样例验收基线

**目标**：消除含混，不写一套庞大规格。冻结四材料、课堂ID、课程别名、文件位置、题库来源、HTML静态策略、旧路径兼容与文章标题规则。

产出一份简短作者契约、一组合法／非法元数据例子、一个来源明确的试点包清单。记录本例D/KD需核对事项；样例原文件保持不动，后续正式内容PR由负责Agent修订派生产物。

验收：第三方Agent只读契约就知道该交哪六个核心文件、不要交什么、在哪个学科和课堂发布。README的人类说明可辅助识别，但生产目标最终由JSON确定。

### P1：打通只读文章链——目录、注册、导航、四材料、窗口

**目标**：一课四篇能真实打开，旧内容无回归；此阶段不对外宣称完整出题闭环。

主要接点：`lib/types/content.ts`、新的课堂schema／生成器、`lib/content-data/manifest.ts`适配、`scripts/gen-nav-manifest.ts`、loader／contentPaths／pathGuard、page／ContentPageClient、FileTree／MobileChapterPicker／SiblingFilesPanel、MemoryCard和引用窗口格式分发。

新增模块保持小而单一：课堂schema、课堂目录生成、统一材料读取、HTML阅读器、有效内容上下文解析。不要散落十多个“如果category===recording”的分支；也不一次重写旧业务接口。

可以拆为两个可审核代码批次：先落schema／生成／路径与单元测试，再落UI／手卡／窗口并对样例验证。生成数据中不夹正文，客户端依赖不包含fs。

验收：四种文章在桌面／手机可达；原文无加工丢失；纪要结构清楚；HTML页完整且窗口可用；手卡支持完整表格／公式；旧rec/sum和概率论路径不变。未实现精确HTML锚点时明确回退到文章／页，不伪造定位。

### P2：打通学习闭环——题库、文本表示、引用、索引与PR门禁

**目标**：原文＋HTML笔记能稳定支撑本课题库；题目入口不受格式限制；发布版本一致。

主要接点：categoryKeys／中央context、`lib/stores/ui.ts`、QuizTab输入、quiz数据校验与版本、内容文本提取、chunker输入、`/api/section`兼容／新版入口、NoteCitationViewer。Agent工具仅对接内容层读取接口，不进入运行时重构。

增加针对新目录的完整性校验、指令校验、静态HTML检查、题源角色与hash校验、生成物一致性检查。构建链显式执行相应内容测试；不能靠当前默认prebuild代替。

验收：切换四篇文章始终关联同一本课题库；错误学科／过期源hash拒绝；HTML能够被检索、读取和引用打开；修改纪要／手卡不要求重新出题；原文／笔记变化让旧题库进入待重验；回滚恢复同版产物。

### P3：真实试点与逐科推广，再启用学科其他资料

先使用这份分析化学样例作为第一课，补齐经过核对的题库；第二份选实际有图或不同结构的学科材料（如组胚／解剖）。上游负责获取材料，不为测试编造课堂。

先验证手工确认合并的一轮，再逐步开启满足门禁的常规自动合并；只有新增课堂稳定后才扩展自动修订、独立extras。全量历史搬迁、跨分类快捷方式、SRS和更多HTML脚本模板均不作为首个闭环前置条件。

### 阶段依赖与可停止边界

```text
P0契约 → P1四文章可读 → P2题目／检索／发布一致 → P3真实自动化推广
```

每阶段都可以单独审核、回退。P1完成能验证阅读价值，但不是完整自动化；P2缺任一读取消费者接入，需明确未完成入口，不能用主页面截图代替全部可达性。工作量不以“一个注册表小改”估计；真实成本集中于P1/P2跨消费者一致性，具体工期应在实施分支初检后评估，而非本轮凭空承诺。

## 12. 验收矩阵与失败处理

| 场景 | 应有结果 |
|---|---|
| 一份第7—8节包导入 | 一个课时组、四篇文章、一套题；不拆成第7和第8两套 |
| 重复导入相同内容 | 无无意义文件变更、无重复PR、无重复出题 |
| 节次与全天课表不同 | 保留课程内节次；实际主题不被课表主题覆盖 |
| 原文含尖括号、指令、时间与学生短句 | 原样可读，不执行、不丢失、不被Markdown解释 |
| 纪要含粘连列表与多个H1 | 适配后层级清楚；事实、限制条件和必要定位保留 |
| 手卡含表格、块公式、下标 | reveal模式完整渲染，旧cloze／清单行为不变 |
| 手卡超长或嵌套不支持指令 | 指明卡片和规则，拒绝静默有损回退 |
| HTML静态7页 | 手机／桌面可读，未裁切，窗口进出正常 |
| HTML链接测试包 | 外链、锚点、相对资源可用；危险协议／越权资源被拒绝 |
| 点击搜索所得HTML／原文引用 | 打开正确格式正文，不落到“只有片段” |
| 切不同课或不存在题库 | 不复用上一课quizKey／答案状态 |
| 题目引用纪要／手卡 | 题源校验失败；不能以其位于同一文件夹为理由放行 |
| HTML与手卡复制同一错误 | 不当作双源证明，关键问题交内容负责方核验 |
| 改纪要或手卡 | 不触发本课重出题，但内容显示／检索版本要更新 |
| 改原文或笔记实质内容 | 校验题库输入版本，未更新则阻止完整发布 |
| 当前PR追加提交 | 重新校验当前head，不复用旧通过结果 |
| 未知学科／材料／夹带脚本 | 待映射或拒绝，不扩权猜测 |
| 缺一材料、资源404、索引过期 | 明确失败步骤，保留旧发布 |
| 生化已有sum-01 | 原文和URL保留，不覆盖或重新绑定 |
| 旧有教材／章节／题库 | 既有路径、默认能力、题目与窗口无回归 |

验证建议分三层：schema／纯函数测试全自动；使用真实四材料进行SSR与组件测试；桌面／手机浏览器验证窗口、排版和点击。语义正确性独立抽查。失败报告应给出课堂ID、文件、题号／卡号、规则和修复建议，而不是只报“构建失败”。
