01怎么读这份对比

02能力雷达

六个维度，满分 10。评分不是读观感，而是按「可核验断言的命中率」「是否到 file:line」 「独立发现且经核实的真缺陷条数」「是否给已损坏的机制打了好评」四类证据回推的。点击图例可切换显示。

「抗幻觉」= 未被核验证伪的断言占比，分数越高越可信。
「缺陷发现力」按经核实的真阳性条数归一化，非自称条数。

03逐项评分

04发现量与采信判定

「真阳性」= 该报告提出、且本次核验在源码中确认成立的独立缺陷（多份重复提出的只在各自计一次）。 「证伪」= 被核验推翻的断言，包括对已损坏机制给出的正面评价。

为什么 Claude Opus 4.6 的真阳性只有 7 条？ 它的架构叙述与数据流表基本准确，问题出在结论方向：给 Prefix Cache 优化打了 ⭐⭐⭐⭐⭐、 给模型接入打了 ⭐⭐⭐⭐⭐。而这两处恰好各藏着一个 P0——用户提问被写进 system 导致每轮 cache 失效， 以及 GLM 降级到 MiMo 后思考方言不切换。把损坏的机制评为满分，比漏看它更有害， 因为它会让人不再去查。

05耗时与额度估算

牌价按 2026-09-12 各家官方 API 标价重核过；「本次实付」按实际走的通道另计。 Token 量仍按 harness 形态推算：子智能体扇出是主导变量——14 路并行大致等于把代码库读 14 遍。 走 IDE / 会员订阅时，这个差额用户感知不到；换成官方按量 API，差距就会露出来。

牌价来源（每百万 token，缓存未命中）。 Grok 4.6：xAI $2 / $6（prompt ≥200k 整单翻到 $4 / $12）； Kimi K3 官方：Moonshot $3 / $15（缓存命中输入 $0.30）——官方并不便宜； K2.8：Kimi 开放平台尚未单独挂牌，coding 档按官方 kimi-k2.7-code $0.95 / $4 作近似； Claude Opus 4.6：$5 / $25（不是旧 Opus 4 的 $15 / $75）； Gemini 3.7 Flash 入门价：$0.75 / $3.75（至 2026-12-31）。 未计入 cache 折扣。K3 本次没有走官方 API，走的是商汤日日新 Token Plan，公测期单价基本上是免费的。

06成本效率

左边按官方牌价算「假如全部走按量 API」；右边是这次真实通道。两列不能混着比。

K3 看起来便宜，便宜的是通道，不是官方牌价。 Moonshot 官方 K3 是 $3 / $15，比现在的 Grok 4.6（$2 / $6）还贵一档。 这次 K3 实付≈0，是因为走了商汤日日新（Token Plan 公测，单价基本为 0），不是因为 K3 本身是廉价模型。 按官方牌价，单位成本最低的是 K2.8 近似档和 Gemini；按绝对覆盖，仍然只有两份 Grok 摸到安全面、卫星路由、持久化孤立键——8 条安全类 P0 的唯一来源。

两份 Grok 若按 xAI 牌价约 $33（未计 ≥200k 加价；加上大约翻倍）。 实际走 Cursor / Grok CLI 订阅，这笔感知不到。用订阅额度换 8 条安全 P0 + 步数触顶静默失败—— 对一个准备把自定义 baseUrl 和用户密钥推到前线的项目，仍然划算。

07各报告定性

08Harness 形态的影响

这次对比里，Harness 形态对结果的影响不亚于模型本身。三条可观察的规律：

  • 扇出决定覆盖广度，不决定准确率。 Cursor Grok（14 路）与 Grok CLI（16 路）同模型同量级扇出，独立跑出高度一致的结论—— 这本身就是交叉验证。而单智能体的 Kimi K3 准确率并不低（8.5），只是覆盖不到 5.0： 它说的都对，只是没时间说完。
  • 只读约束显著抑制幻觉。 两份 Grok 报告都明确声明「子智能体不改仓库，只回传带行号的机制」， 并要求断言可回溯到 file:line。抗幻觉得分 9.5 / 9.3，明显高于自由叙述型报告。 Gemini 缺这层约束，于是出现了「Agent 会挂起等待用户批准」这种读了类型定义就以为读了实现的错误。
  • 被问题措辞带偏的风险是真实的。 「Harness」被 Gemini 解成了「H = Hybrid Search / Human-in-the-loop / History / Heartbeat」， 整整一章建立在这个自造框架上。同一个词，另外五份都正确理解为 Agent 运行底座。 这不是知识缺陷，是遇到不确定术语时选择编一个自洽解释、而不是回代码求证。

09各模型在工程中的实际用法

分数之外，还要看它们平时被放在哪条流水线上。用量、订阅结构和宿主产品，会反过来解释「为什么这份报告写得深 / 写得浅」。

Cursor Grok · 300K Grok CLI · 500K

Grok 家族：日常主力，因为便宜

Cursor Grok、Grok CLI，以及同一条线上的 Grok，能被大量使用，首先是因为相对成本很低、订阅给的额度非常多。 不是「先证明它最强再决定多用」，而是便宜到可以拿复杂仓库反复扫，覆盖和交叉验证才堆得起来。 Cursor 侧有完整适配；CLI 侧靠子智能体扇出——能力强没有问题，但那是组合拳，不是裸模型榜。

Claude Opus 4.6 Thinking Gemini High

AntiGravity：Claude 与 Gemini 的宿主

这两份都跑在 AntiGravity 里。Claude 的架构叙述能用，但会给已损坏机制打满分——偏差在判断，不在认不出仓库。 Gemini 则更明确：主要是模型本身的问题（自造 Harness 框架、把类型定义当成实现）。 换宿主也救不了「不确定时编一个自洽解释」。

Kimi K2.8

Kimi Code：K2.8 的工程现场

K2.8 用在 Kimi Code。4 路并行，架构判断力是六份里最清楚的一档（「工具无副作用化」、 "upstream" 命名空间靠人记住）。安全面缺席，所以适合当「结构校对」，不适合当「边界巡逻」。

Kimi K3

日日新 API + DeepSeek Harness

K3 官方 API 相对贵（Moonshot $3 / $15）。这次没走官方，而是商汤日日新 + DeepSeek harness—— 日日新 Token Plan 公测期单价基本上免费。所以「K3 这次很便宜」说的是通道，不是牌价。 篇幅最小、信噪比最高，compaction 是它先立成 P0 的。准确率不低，覆盖被单线程卡住。

10综合评价与使用建议

把价格、订阅额度、上下文窗口、harness 扇出、宿主产品和这次核验结果叠在一起，而不是只看均分。 我自己常用的这几档，综合成本都相对低，适合日常。要看清模型之间的差距，最好拿一个足够复杂的大项目做同一套审查——这次就是那把尺子。

01 · 日常工程

Grok 系列当默认循环

Cursor Grok / Grok CLI 订阅便宜、额度多，值得占日常工时的大头。复杂勘察、安全面、持久化这类「不主动找就看不见」的问题，这次只有它们摸到。 把它理解成低成本 × 强 harness，而不是「Grok 一定比别的模型聪明」。

02 · 架构校对

Kimi 用来对结构、控预算

K2.8（Kimi Code 订阅）适合要一条设计原则、一张结构图的时候。 K3 只有挂在日日新这种近乎免费的通道上，才适合当日常低成本探针； 若走官方 Kimi API，$3 / $15 并不划算。两者都别单独指望扫完安全面。

03 · AntiGravity

Claude 看地图，不看星级

Opus 4.6 Thinking 的数据流表和能力矩阵可以给新人建立整体认知。不要采信它对 Prefix Cache、模型接入的满分—— 这次核验说明：方向对、评分不可用。改进建议（Orchestrator、渐进压缩）可以当议题，不能当结案。

04 · 机制断言

Gemini 先复核再引用

分层图和接入指南能用；§4 自造框架与 HITL 结论不能用。问题主要在模型：读到类型就当实现、不确定术语就编框架。 AntiGravity 换不了这件事。机制层句子必须回源码。

如何用一次复杂审查判断差距。 日常小改、补类型、写单测，便宜模型之间几乎分不出高下。把同一套问题扔进一个有循环、有上下文工程、有自定义模型接入的大仓库， 差距才会稳定出现：谁能钉到 file:line，谁会给坏掉的机制打五星，谁会把 Harness 编成四个 H。 本次 13 条 P0 / 62 条 P1 / 11 条证伪，就是那次实验的刻度。选用时同时看三件事： 你付得起多少扇出、宿主有没有只读约束、这份输出能不能当施工蓝本。
