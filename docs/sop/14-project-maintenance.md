# SOP 14 — 项目维护与职责重构

## 适用场景

职责拆分、目录整理、重复/死代码处理、框架升级和文档维护。当前人类任务决定范围；旧交接和归档队列仅供解释历史。

## 输入与依据

[AGENTS.md](../../AGENTS.md)、[当前架构](../architecture.md)、[组织标准](../standards/code-organization.md)、被改领域参考、源码及实际消费者。Next 行为优先结合安装版 `node_modules/next/dist/docs/`，[官方快照](../vendor/nextjs/2026-10-10/README.md) 保存来源和哈希。

## 操作步骤

1. **建立当前基线**：检查分支、远端、工作区、实际版本和已运行服务；保留无关修改。记录当前需求、完成标准和不可丢失的契约。
2. **按调用链审查职责**：使用 architecture inventory 查看长文件、拥挤目录、运行/类型/延迟依赖。行数是审查信号；拆分依据是独立变化原因，不能只按行号切片。
3. **明确状态所有权**：一个 store、队列、checkpoint 引擎或窗口状态仍由一个入口拥有。子模块通过窄接口或同一 set/get 组合，不再建第二份权威状态。
4. **更新实际消费者**：静态/动态导入、Worker、CLI、Electron、服务端与客户端入口、测试 mock、源码路径断言、tracing 和活文档同时核对。只在确有消费者契约时保留明确公共入口；不用全套转发壳代替迁移。
5. **审查重复与未使用**：先完善 Knip 的 Next、Classolo、Worker、脚本和沙箱入口，再追踪消费者。相同名称不是相同算法；数学误差、排序、边界与依赖一致才能复用。确认淘汰后保留可恢复原件与原因。
6. **维护文档**：实现说明进入 refer，长期规则进入 standards，步骤进入 SOP，任务证据进入 plans/analysis。失效记录归档并登记原路径/日期/替代入口，不继续让旧账本成为“唯一当前状态”。
7. **验证与提交**：按 [测试 SOP](07-testing.md)运行定向检查，当前阶段只提交本阶段文件；最终候选统一做全量门禁、生产构建与真实页面验收，报告实际覆盖和未验边界。

## 必须保持的契约

账号身份/所有者、统一计费、账户隔离、持久化 key 与迁移次序、原子 checkpoint/CAS、完整历史、失败恢复、取消、附件原件和派生上下文、Web/Electron 边界，以及现有 URL 和交互。修复已有错误时明确写出触发、前后差异和独立验证；不能把行为修复冒充结构完全等价。

本机已有服务优先复用，恢复前重新核对当前进程、HTTP 和页面状态。构建/测试的资源上限是验证资源管理，不能据此宣称运行性能提升。生产迁移、部署、发布和付费调用不是普通代码整理的自动下一步。

## 归档与检查

原件要能恢复；记录 source、destination、原因和哈希。若承诺字节原件，检查 Git 中实际 blob 的哈希并为对应快照保留行尾；不能只有复制前/本机比较成功而远端内容已被转换。

历史文档正文不为凑当前链接通过而批量改写。活文档的引用更新到新入口，原相对路径的解释保存在归档索引；缺失的旧验收附件不伪造补齐。Markdown 示例应与真实链接分开检查。

工具：[源码清点](../../scripts/maintenance/architecture-inventory.mjs)、[文档链接检查](../../scripts/maintenance/check-doc-links.mjs)、[当前系统整理记录](../plans/2026-10-10-project-refactor-execution.md)。这些静态报告是线索，不独自证明功能、性能或部署完成。
